# Live View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Shopify-style Live View on `/live`: visitors right now, shopper behaviour, today's provisional sales, top products and recent activity, computed from Flink's clean event topic.

**Architecture:** A new `live-events-worker` projects `marketing.clean.customer-events.v1` into `marketpulse_live.events` (ReplacingMergeTree by Kafka position). A `LiveViewService` computes every block with ClickHouse SQL anchored at the latest eligible event time; FastAPI serves it at `GET /api/v1/live/view`; the Next.js Live page renders it above the existing campaign snapshot table.

**Tech Stack:** Python 3.12, confluent-kafka, clickhouse-connect, FastAPI, Next.js 16 / React 19, shadcn/ui, Recharts, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-31-live-view-design.md`

## Global Constraints

- Every number is labelled provisional; nothing is added to certified values.
- "Now" = latest eligible `event_time`; never the wall clock.
- Eligible = `eligible_for_aggregates AND consent_analytics AND session not bot`.
- Active window 30 minutes; series 30 one-minute buckets; top products 5; feed 12 events.
- Money: integer minor units; API values are strings (`wire`); conversion uses `marketpulse_app.math.ratio`.
- API never returns customer, anonymous, session, order or event identifiers.
- Consumer group `marketpulse-live-events-v1`, `read_committed`, offsets committed only after insert.
- Commit messages: conventional prefix, no attribution trailers of any kind.

## Review Focus

1. Duplicate delivery after a crash (same partition/offset inserted twice) must not double counts — tests read with `FINAL`.
2. A day with sessions but no orders (no currency) must render zero money, not crash.
3. A product with no certified label shows "Unlisted product", never a raw id.
4. A bot session or a consent-denied visitor must not appear in any block.
5. Empty projection (worker not started) returns `status: "empty"` and the page says so.
